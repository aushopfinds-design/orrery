# 사이트 화면과 사용 흐름 정리

사용자 요청: 사업 등록과 결제 연결보다 사이트 완성을 먼저 진행한다. 기존 도메인, GitHub 저장소, Vercel 프로젝트와 승인된 금빛 열쇠 그림을 유지한다.

## 이용 흐름

- `#birth-details`: 전 세계 국가·지역과 도시 검색, 직접 좌표 입력, 실제 출생지 현지 시간으로 계산한다.
- `#free-reading`: 쉬운 영어로 무료 결과를 먼저 보여준다. 전문 계산 탭은 별도 펼침 영역 안에서 이용한다.
- `#my-report` 및 종류별 경로: 같은 출생 정보로 7종 개인 미리보기를 살펴본다. 궁합과 묶음에는 두 번째 사람의 정보가 필요하다.
- 전체 예시는 가상의 사람을 사용한다. 결제 완료나 유료 구매자의 전체 보고서처럼 표시하지 않는다.
- 단계 안내와 현재 메뉴 표시, 페이지 제목, 도움말 링크를 연결한다.

## 새 안내 화면

- `#help`: 출생 정보, 보고서 선택, 저장·인쇄, 개인정보 안내와 FAQ.
- `#reading-guide`: 현지 시간과 출생지 입력, 7종 보고서의 차이·구성·필요 인원, 강조 문장과 실천 안내, 저장·인쇄 방법.
- `#your-data`: 현재 브라우저 저장 상태, 실제 저장 위치와 외부 요청, 백업 파일의 특성, 개인 읽기 정보 삭제 기능.

개인정보 화면은 현재 프로그램의 동작을 설명한다. 사업자 신원, 법적 인증, 확정 환불 조건, 가짜 연락처를 만들어 넣지 않는다.

## 저장과 복구

- 저장창을 열 때 실제 저장 목록을 다시 읽는다.
- 개인 미리보기에서도 현재 첫 번째 사람의 실제 출생 정보를 저장할 수 있다.
- 손상된 JSON과 잘못된 날짜·좌표·도시·국가 조합을 걸러낸다.
- 백업 가져오기는 기존 이름별 정보를 보존하고 중복 ID를 추가하지 않는다.
- 저장 실패와 백업 읽기 결과를 안내한다. 키보드로 저장 항목을 열고 수정·삭제할 수 있다.
- 개인정보 삭제는 확인과 취소를 거치며 출생 정보·이름별 저장 정보·현재 탭 미리보기만 제거한다. 언어 설정 등 다른 데이터와 다운로드한 백업 파일은 제거하지 않는다.

## 구현과 검증

- 출생 정보 변환·검증은 `src/utils/birth-form-state.ts`, 저장은 `profiles.ts`, 개인정보 삭제는 `reading-data.ts`에서 관리한다.
- 전문 차트와 복사용 계산 모듈은 사용할 때 불러온다. 초기 JavaScript 묶음은 약 1.17 MB에서 0.52 MB로 줄었다. 실제 통신 속도나 체감 속도를 측정한 수치는 아니다.
- 저장·복구·가져오기·데이터 삭제와 전체 보고서 경로를 포함한 Vitest 352개 검사 통과.
- 수정한 TypeScript/React 파일 ESLint와 TypeScript/Vite 빌드 통과.
- 이번 환경에는 Sites 관리형 미리보기의 필수 브라우저 도구가 없으므로 개발 서버를 임의로 띄우거나 다른 브라우저 경로로 QA를 우회하지 않았다. 반응형 규칙과 인쇄 숨김 규칙은 소스에서 검토했으며, 실제 모바일·브라우저 화면 검증은 남아 있다.

## 다음 단계

실제 결제, 서버에서 확인한 결제 상태에 따른 전체 개인 보고서 발급, 주문 영수증과 고객 문의·사업자 정책은 아직 연결하지 않았다. 화면에는 유료 구매가 열리지 않았다는 안내를 유지한다. 관련 구현은 `PAID_LAUNCH_GATE.md`의 준비 항목을 실제로 충족한 뒤 진행한다.
